# Security Policy

## Supported reporting path

If you discover a security issue, do not open a public issue. Use GitHub's private security advisory flow for this repository instead.

When reporting, include:

- the affected version or tag
- the platform and runtime environment
- reproduction steps
- the security impact
- any available proof of concept

## Response expectations

Security reports should be treated as confidential until they are fixed or otherwise disclosed.

If private advisory reporting is not available, create a normal issue with only the minimum information needed to route the report and mark it as security-sensitive.
